# Анализ REST API сервиса client-info

## Обзор

Сервис client-info предоставляет REST API для управления клиентскими данными. Из-за большого объема данных (до 500 атрибутов) API разделен на отдельные ресурсы для разных типов данных.

## Ключевые ресурсы и операции

### 1. Клиент (Client)
**Эндпоинт:** `GET /clients/{id}`

**Описание:** Получение базовой информации о клиенте по ID

**Возвращаемые данные:**
- `id` (string) - идентификатор клиента
- `name` (string) - имя клиента
- `age` (integer) - возраст клиента

**Проблема:** Возвращает только базовую информацию, не включает связанные данные (документы, родственники)

### 2. Документы (Documents)
**Эндпоинт:** `GET /clients/{id}/documents`

**Описание:** Получение списка документов клиента

**Возвращаемые данные (массив Document):**
- `id` (string) - идентификатор документа
- `type` (string) - тип документа
- `number` (string) - номер документа
- `issueDate` (string) - дата выдачи
- `expiryDate` (string) - дата окончания действия

**Проблема:** Требует отдельного запроса для получения документов

### 3. Родственники (Relatives)
**Эндпоинт:** `GET /clients/{id}/relatives`

**Описание:** Получение информации о родственниках клиента

**Возвращаемые данные (массив Relative):**
- `id` (string) - идентификатор родственника
- `relationType` (string) - тип родства
- `name` (string) - имя родственника
- `age` (integer) - возраст родственника

**Проблема:** Требует отдельного запроса для получения родственников

## Выявленные проблемы

1. **Множественные запросы:** Для получения полной информации о клиенте требуется 3 отдельных HTTP-запроса:
   - GET /clients/{id}
   - GET /clients/{id}/documents
   - GET /clients/{id}/relatives

2. **Увеличение нагрузки:** Каждый запрос создает отдельную нагрузку на сервис, увеличивая RPS

3. **Over-fetching:** Невозможно получить только нужные поля, всегда возвращаются все поля ресурса

4. **Under-fetching:** Невозможно получить связанные данные в одном запросе

## Преимущества GraphQL

1. **Один запрос:** Все необходимые данные можно получить в одном запросе
2. **Гибкость:** Клиент выбирает только нужные поля
3. **Связанные данные:** Можно запросить клиента вместе с документами и родственниками
4. **Снижение нагрузки:** Меньше запросов = меньше RPS
